# Standard web Socra

Proprietario delle regole: backend `docs/wiki/12-security-baseline.md` sul ref corrispondente a questa release. Questo ingresso accompagna il repository frontend anche fuori dal workspace.

Mutazioni cookie-based: `guardMutation` prima di rete/mutazioni; Origin esatto da `SOCRA_PUBLIC_ORIGINS`, nessuna fiducia in Host inoltrato. Production default socra.it/www.socra.it; ambienti di test aggiunti esplicitamente. JSON e streaming limitati tramite `readJsonBody` (azioni account 16 KiB, dominio 256 KiB); unica eccezione `PUT profiles/me/avatar` 3 MiB per il file UI massimo 2 MiB espanso in base64. Metodo/percorso diversi mantengono il limite normale. Logout e proxy senza body ammessi. Risposte/errori privati tramite `privateJson`. Auth restituisce solo user_id, bearer soltanto nel cookie.

Il proxy generico accetta segmenti semplici ASCII e soltanto `GET auth/me` del namespace auth. Nuove route auth richiedono un handler dedicato; richiesta verifica email usa helper con percorso fisso, sessione e guardie normali, senza aprire auth nel proxy generico. Vietati percorsi codificati/ambigui e dot traversal che fetch potrebbe normalizzare verso un endpoint con token.

La CSP è in `proxy.ts`, nonce casuale per richiesta e layout dinamico. Script production senza unsafe-inline/eval; stili inline conservati per UI. Non abilitare cache condivisa HTML/RSC in Railway/Cloudflare: nonce e contenuto personale non devono essere riutilizzati. Gli asset statici conservano la cache framework. Nuovi script esterni richiedono revisione CSP e test browser. Non introdurre HSTS prima del collaudo dei domini HTTPS.

CI verifica route reali con upstream finto al solo confine rete, build/lint/typecheck, audit dipendenze high e Chromium/mobile per CSP/hydration. Le prove con mock non attestano API/Google produzione. Baseline pubblicata il 27/09/2026 su conferma GR, su `release/v3-20260919`: frontend applicativo `8b2275f`, backend `38368ab`, successivo aggiornamento solo documentale. Il rapporto canonico backend `docs/releases/2026-09-27-security-production.md` attesta deployment, migrazione, conservazione dati e smoke HTTP/browser live. Nessun nuovo deploy o ampliamento integrazioni implicito dalle modifiche future.

Dashboard privata pubblicata successivamente il 27/09: frontend `3d6cb79`, backend `71c09fa`, rapporto canonico `docs/releases/2026-09-27-monitoring-production.md`. Namespace monitoring sempre escluso dal proxy generico; BFF dedicato con Origin canonico e 16 KiB. Cookie login allineato a scadenza backend (operatori autorizzati fino8h, utenti ordinari invariati); cookie MFA Strict fino8h/sessione con revoca server. Eccezione CSP per HTML statico gated: script-src self, solo asset locali senza inline/eval. React MFA e resto app conservano nonce/strict-dynamic. Verificati browser produzione per entrambi gli operatori, login/logout, cookie8h, dati negati senza MFA e fattori personali ancora da configurare.

## Eccezione audit temporanea — 03/10/2026

Decisione tecnica per questa release, registrata anche nella wiki12 proprietaria: `npm run audit:security` esegue audit npm completo e `--omit=dev`, conserva i JSON e l'esito in `.local/security-audit/` (artifact CI `npm-dependency-audit`). Il report completo corrente ha **5 high**, derivati da **un solo advisory**, [GHSA-vfj7-8cjw-p6xm / CVE-2026-93687](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm). Il 03/10 registry e advisory non offrono una versione corretta di braces; la [PR upstream #72](https://github.com/micromatch/braces/pull/72) è ancora aperta. Anche il plugin Next 16.3.8 conserva fast-glob 3.3.1. Nessun downgrade Next, aggiornamento runtime o esclusione globale delle dipendenze dev.

L'unica eccezione è la catena verificata `eslint-config-next@16.3.6 → @next/eslint-plugin-next@16.3.6 → fast-glob@3.3.1 → micromatch@4.0.8 → braces@3.0.3`, tutta `dev: true` nel lockfile. Quel parser riceve glob configurati dagli sviluppatori; Socra non gli passa input utente e non configura `settings.next.rootDir` (verificato anche sulla configurazione ESLint effettiva di `app/page.tsx`). L'audit `--omit=dev` riporta zero vulnerabilità. Questo delimita la catena segnalata: **non attesta l'assenza di ogni copia di codice vendorizzato nel runtime Next**.

L'eccezione scade al primo istante del **10/10/2026 UTC**, `2026-10-10T00:00:00.000Z`, e va rimossa prima se upstream fornisce una soluzione adottabile. Il gate blocca alla scadenza se l'eccezione è ancora necessaria; un audit realmente pulito non la usa. Blocca inoltre su errori/rete/timeout/JSON o schema invalidi, conteggi incoerenti, nuove advisory di qualsiasi severità, qualunque finding runtime, nodi/versioni/archi/consumatori diversi della catena, flag dev assente e nuova configurazione `rootDir`. Mantiene visibili `5 high` e `1 known exception`; non converte questo esito in zero vulnerabilità totali. Nessun flag o variabile CLI permette di estendere l'eccezione o la sua scadenza.

Regressioni in `tests/dependency-audit.test.mjs`, incluse in `npm run test:security`: report npm catturati e mutazioni ostili, limite temporale UTC, advisory uguale nel runtime, advisory aggiuntiva sulla stessa dipendenza, catena/versione/consumatore diversi, errori processo/rete/JSON e CLI reale con il solo processo npm simulato. Il comando reale contro il registry resta una verifica distinta dalle fixture.
